# コーディング規約

姉妹リポジトリ（`../impulsive-momentum-indicator/.claude/rules/coding-standard.md`）の規約を基本とし、地球の描画と演出に関する決まりを加える。技術スタックは `.claude/rules/tech-stack.md`、仕様は `docs/user-story-map.md` を参照する。

## 全般

- コード内のコメント、テスト名、コミットメッセージの本文は日本語。識別子（変数名・関数名・ファイル名）は英語。
- コメントは「なぜそうするか」を書く。
- 仕様に対応するコード・テストには、必要に応じて USM の ID（例：`US-4.2`）を書く。
- 未確定事項（USM の Q-xx／T-xx）に依存する箇所は独断で実装しない。暫定実装する場合は `// TODO(Q-06): …` のように ID を残す。
- 使われていないコード、デバッグ用の `console.log`、コメントアウトしたコードを残さない。

## TypeScript

- `strict`。`any` を使わない（`unknown` から絞り込む）。`as` と `!` は避ける。
- 衝動の種類と順序は1つの定数配列（`IMPULSE_KEYS`）から導く。コード中に重複して書かない。
- 上限（10票）、ウィンドウ（12時間）、演出の確率・閾値などは名前付き定数にする。
- 時刻はエポックミリ秒の `number`。

## ディレクトリと責務（Nuxt 4）

| 場所 | 責務 |
|---|---|
| `app/app.vue` | メイン画面1枚。ページ遷移を作らない |
| `app/components/` | 表示コンポーネント（横スクロールの枠、スライド、投票操作、数値表示） |
| `app/components/worlds/` | 衝動ごとの地球と演出（例：`WorldIkki.vue`）。衝動ごとに別コンポーネントでよい |
| `app/composables/` | 画面の状態と操作。`use` で始める |
| `app/domain/` | 画面だけが使う純粋なロジック（**演出の抽選・集計値から演出強度への対応**、緯度経度から地方への変換など）。Vue・Nuxt を import しない |
| `shared/domain/` | 画面と Lambda で共有する純粋なロジック（衝動、上限・ウィンドウ、寄与度、地域コード）。規約は `.claude/rules/infra.md` |
| `app/data/` | World API との通信（集計状態の取得・投票の送信）とモック実装。姉妹リポジトリの `ImpulseCountSource` と同じ考え方の境界 |
| `app/visuals/` | 描画エンジン（T-02 で決めた方式）の初期化・破棄・描画ループ。Vue に依存させすぎない |

- `server/` は作らない。バックエンドは `infra/`（`.claude/rules/infra.md`）。
- 上限・ウィンドウ・寄与度・地域の定義を `app/` に書き直さない。`shared/domain/` を import する。

## 投票・集計のロジック

- 姉妹リポジトリの `app/domain/`・`app/data/` の考え方を引き継ぐ（流用はコピーし出典を残す。T-03）。
  - 判定は現在時刻を引数で受け取る純粋関数。`Date.now()` を直接呼ばない。時計と乱数は注入する。
  - 投票は楽観的更新。票には一意な ID を付ける（冪等）。
  - 集計数の取得・投票・上限判定はデータ層のインターフェース経由。画面はモックか API かを知らない。
- **上限の最終判定はサーバー**。クライアントの判定は表示のためのもの。

## 演出のロジック

- **一時的な演出（投票ごと）と持続的な状態（集計結果）を別の入力・別のモジュールにする。** 持続的な状態は集計数だけから決め、投票操作のイベントで直接変えない。
- 演出の抽選は `app/domain/` の純粋関数にし、乱数を注入する。通常・特殊・レアの確率は定数で持ち、直前の演出を避ける仕組みもここに書く。単体テストで確率の境界と連続回避を検証する。
- 集計数 → 演出強度の対応（非線形の曲線）は純粋関数にする。**表示する数値はこの関数を通さない**（実数をそのまま表示する）。
- 演出は投票操作をブロックしない。連打中も入力を受け付け、同時に走る演出の数に上限を設けて古いものから間引く。

## 描画と性能

- 表示中の衝動の地球だけを描画する。非表示の画面は描画ループを止める。
- タブが非表示（`visibilitychange`）のときは描画ループを止める。
- `devicePixelRatio` に上限を設け、低性能端末向けに粒子数などを減らせるようにする。
- コンポーネントの破棄時に WebGL コンテキスト・テクスチャ・イベントリスナー・タイマーを必ず解放する。
- `prefers-reduced-motion: reduce` では常時の装飾アニメーション（自転・浮遊など）を止めるか弱める。投票時の演出を残すかは Q-09。

## Vue コンポーネント

- `<script setup lang="ts">`、Composition API。props／emits は型で定義する。
- コンポーネントに投票・上限・集計・抽選のロジックを書かない。

## スタイル

- `<style scoped>`。共通の値・衝動ごとのテーマ色は CSS カスタムプロパティ。
- モバイルファースト。文字サイズ・余白は `clamp()` などで伸縮させる。
- DOM のアニメーションは `transform` と `opacity` を中心に使う。

## アクセシビリティ

- 操作要素はネイティブの `<button>`。アクセシブルな名前を付ける。フォーカスリングを消さない。
- 地球の描画（canvas）は装飾として扱い、衝動名と集計数はテキストでも読めるようにする。
- 非表示の衝動のスライドは `aria-hidden="true"`、中の要素を Tab で辿れないようにする。
- 残り枠・上限の変化は `aria-live="polite"` で通知する。
- 文字と背景のコントラスト比 4.5:1 以上（地球や演出の上に文字を重ねる場合も）。

## テスト

- `app/domain/`・`shared/domain/` はすべて単体テスト。上限（10票目可・11票目不可）、衝動ごとの独立、12時間の境界、寄与度、演出の抽選、強度の対応を検証する（`shared/domain/` は今は `infra/test/shared/` で検証している）。
- 時間・乱数に依存するテストは注入した時計・乱数で行う。
- E2E はスマホ（390×844）と PC（1280×800）で、切替・投票・上限の主要な流れを確認する。canvas の中身は E2E で検証しない（描画が始まること・エラーが出ないことだけ）。

## 作業の進め方

- 変更後は lint・型チェック・テストを実行し、通ってから完了とする。失敗が残ればその旨を報告する。
- 1つの変更は1つの目的に絞る。仕様にない機能を「ついでに」追加しない。
