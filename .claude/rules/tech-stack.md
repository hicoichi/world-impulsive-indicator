# 技術スタック

凡例：**【確定】** = 指示で確定済み／**【暫定】** = 提案段階。USM §9 の T-xx でユーザーの確認待ち。暫定項目を変更・確定したら、このファイルと USM の両方を更新する。

## 構成の前提

| 項目 | 方針 |
|---|---|
| フロントエンド | Nuxt ベースの Web アプリケーション【暫定：姉妹リポジトリに合わせる。T-01】 |
| バックエンド | このリポジトリの `infra/` に AWS CDK（TypeScript）で構築する World API【確定】。集計は姉妹アプリと別。規約・技術は `.claude/rules/infra.md`、設計は `docs/world-api-design.md` |
| 共有ロジック | `shared/domain/`（画面と Lambda の両方が import する）【確定】 |
| 対象デバイス | モバイル主軸、PC にも対応するレスポンシブ UI【確定】 |

- Nuxt の `server/` ディレクトリ（Nitro の API ルート）は使わない。バックエンドは `infra/` だけ。
- 外部への通信は、World API と Web フォント（採用する場合）だけ。

## 地球と演出の描画【確定：Canvas 2D】

UI モックが Canvas 2D で描かれていたため、それに合わせた（2026-11-01、docs/frontend-plan.md §2.1）。描画ライブラリは導入しない。以下は検討時の候補の記録。

| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| A. three.js（WebGL） | 3D の地球＋スプライトで人・飛行機・花火 | 地球らしさ、航路・花火の立体感 | バンドルが大きい、モバイルの負荷、低性能端末の代替が要る |
| B. Canvas 2D／SVG | 正射図法の地球を 2D で描き、モチーフを重ねる | 軽い、依存なし | 地球の回転・奥行きの表現に手間 |
| C. A＋B | 3D 地球を基本にし、性能が足りない端末では 2D に切り替える | 両立 | 実装量が倍近い |

- 日本を中心とした地球のテクスチャ・地図データを使う場合は、ライセンスを確認してから採用する。
- 3つの地球を同時に描かない。表示中の衝動の地球だけを描画し、隣の画面は切り替え時に準備する（性能）。

## 採用しないもの

明確な必要が生じるまで導入しない。導入する場合は事前にユーザーに確認する。

- 状態管理ライブラリ（Pinia 等）：composable で足りる
- UI コンポーネントライブラリ・CSS フレームワーク
- グラフ・可視化ライブラリ（グラフは禁止事項）
- 日付ライブラリ
- 認証・分析・広告・トラッキング関連の SDK

## 依存関係の追加ルール

- 新しい依存を追加する前に、上の「採用しないもの」に当たらないか、標準 API で代替できないかを確認する。
- 追加したら理由をこのファイルに追記する。
