### 2.2 モックと実データをつなぐために作るもの

| 項目 | モック | 実装 |
|---|---|---|
| 地域の熱 | 12都市の固定値（ダミー） | World API の `regions`（8地方）から計算する。各地方に代表都市を割り当てる（北海道→札幌、東北→仙台、関東→東京、中部→名古屋、近畿→大阪、中国→広島、四国→徳島、九州・沖縄→福岡）。`unknown` は全国に均等に配る |
| 規模の変化 | 固定（票が増えても群衆・飛行機・花火の量は同じ） | `momentum`（寄与度の合計）から非線形に「にぎわい」を決め、群衆の人数・飛行機の頻度・花火の頻度・粒子の染まり具合に掛ける。票が0でも最低限の演出は残す（USM Activity 1・2） |
| 集計数 | ダミー値＋自分の票 | `votes`（有効投票数）。投票直後は楽観的に +1 |
| 演出の起点 | 常に東京 | 位置情報があれば自分の地方の代表都市、なければ東京（USM Activity 6。位置情報は「次の段階」） |
| レアの強制 | Shift／Alt＋クリック | 本番には入れない（開発用ビルドの設定だけ） |

## 3. 実装方針

### 3.1 構成

| 場所 | 内容 |
|---|---|
| ルート | Nuxt 4（静的生成）。`@nuxt/eslint`（`infra/`・`shared/` も対象）、Vitest、Playwright |
| `app/app.vue` | 画面1枚 |
| `app/components/` | `LoopTrack.vue`（横スクロール・ループ・ドット・矢印）、`ImpulseScene.vue`（1衝動の画面：canvas、情報、ボタン）、`SiteHeader.vue` |
| `app/composables/` | `useWorldState`（10秒ごとの取得）、`useVote`（楽観的更新・上限）、`useLoopTrack`、`useReducedMotion` |
| `app/data/` | World API クライアント（`/v1/state`、`/v1/sessions`、`/v1/votes`）とモック実装 |
| `app/domain/` | 地域→代表都市、熱の計算、`momentum`→にぎわい（非線形）、演出の抽選（レア 7%、直前の回避）。すべて純粋関数でテストする |
| `app/visuals/` | モックの描画エンジンを TypeScript に移植：投影とカメラ、地理データ、背景と地球、日本の粒子、衝動ごとの持続レイヤー、投票の演出 |

### 3.2 描画エンジンの移植の方針

- モックのアルゴリズム・数値（色、大きさ、時間、確率）をそのまま移す。描画結果をモックに合わせることを優先する。
- モックとの違い：
  - **持続レイヤーの入力**を「固定の熱」から「World API の状態」に変える。状態が変わったら、群衆・花火の頻度などを滑らかに追従させる。
  - **投票の演出**は、持続レイヤーと別のモジュールにする（CLAUDE.md の原則）。
  - **3画面で1つの描画ループ**にし、表示中の画面だけを描く。モックは複製を含む5枚がそれぞれ動く。
  - タブが非表示のとき、動きを減らす設定のときの扱いを加える。
  - 同時に走る演出の数に上限を設け、連打でも重くならないようにする。
