## 1. プロダクト概要

### コンセプト

**世界の空気を、衝動で測る。**

社会や世界の情勢に対して、人々がどのような衝動を抱いているのかを、投票と視覚表現によって感じられるWebアプリ。

ユーザーは、自分の中にある衝動を選択して投票する。

その投票は他のユーザーの投票と集計され、衝動ごとに独立した「世界の状態」として可視化される。

本アプリは、単純なアンケートではない。

人々の意志や機運がどの程度高まっているのかを、直感的で楽しいインタラクションと視覚表現によって体験することを目的とする。

### 現在の対象となる3つの衝動

1. 一揆したい
2. 国外脱出したい
3. 祭りたい

※「革命したい」は「一揆したい」と意味が重複するため採用しない。

### プロダクトの基本方針

- シンプルな操作性を維持する。
- 3つの衝動はそれぞれ独立した画面・世界を持つ。
- 横スクロールによって衝動ごとの画面を切り替える既存構造を維持する。
- 投票そのものにエンターテインメント性を持たせる。
- 投票数によって社会全体の機運が高まっていく様子を可視化する。
- 視覚表現は抽象的すぎず、誰が見ても意味を理解しやすい具体的なモチーフを中心とする。
- 初期リリースでは日本版のみを対象とする。

---

## 2. プロダクトの対象範囲と非対象

### 対象

- 衝動ごとの投票
- 投票数の集計・表示
- 投票に対するランダムな演出
- 投票状況に応じた世界のビジュアル変化
- 日本を対象とした地球の表現
- 任意の位置情報を利用した演出
- SNSで共有したくなる視覚体験

### 非対象

- SNSのようなユーザー間交流
- コメント、メッセージ、フォロー
- プロフィールやユーザーコミュニティ
- 投票者の個人情報の公開
- 地域別の詳細な投票結果の分析
- ニュースフィード
- 政治的な運動や組織活動の支援・募集
- 時系列グラフやランキング
- 投票履歴の閲覧機能

本アプリは、人々の衝動を可視化するエンターテインメント性のあるサービスであり、ユーザーを組織化したり、特定の行動に動員したりするものではない。

# 3. User Story Map

## Backbone：ユーザーの主要な体験

1. アプリを訪れる
2. 世界の空気を感じる
3. 衝動を選ぶ
4. 投票する
5. 変化を楽しむ
6. 他の衝動も試す
7. 世界の状態を共有する

---

## Activity 1：アプリを訪れる

### ユーザーの目的

アプリを開いた瞬間に、何をするサービスなのかを直感的に理解したい。

### User Stories

- 初めて訪れたユーザーとして、アプリのコンセプトを説明文を読まなくても理解したい。
- 初めて訪れたユーザーとして、現在の世界の状態を視覚的に感じたい。
- ユーザーとして、すぐに投票操作を始めたい。

### Acceptance Criteria

- アプリを開くと、主要な投票画面が表示される。
- 画面には地球を中心としたビジュアルが存在する。
- 地球は明確に地球だと認識できる。
- 衝動ごとに独立した地球のビジュアルを表示する。
- 3つの衝動を切り替えられることが直感的に分かる。
- 余計な説明や操作要素を増やさない。
- 投票数が少ない場合でも、地球そのものの基本演出によって画面の魅力を維持する。

---

## Activity 2：世界の空気を感じる

### ユーザーの目的

それぞれの衝動が、現在どの程度広がっているのかを直感的に感じたい。

### User Stories

- ユーザーとして、一揆したい人が多いほど、一揆の機運が高まっている様子を見たい。
- ユーザーとして、国外脱出したい人が多いほど、国外脱出の機運が高まっている様子を見たい。
- ユーザーとして、祭りたい人が多いほど、祝祭の機運が高まっている様子を見たい。
- ユーザーとして、数字だけでなく、視覚的な変化から世界の状態を感じたい。

### Acceptance Criteria

- 衝動ごとに独立した地球のビジュアルを持つ。
- 3つの衝動のビジュアルは、それぞれ異なる表現・モチーフを使用する。
- 投票数が増えるほど、その衝動を象徴する現象の規模・頻度・密度・にぎわいが増す。
- 投票数が少ない場合でも、基本的な地球の演出は維持される。
- 実際の集計結果に基づく持続的な変化と、一時的な演出は区別する。
- 数字の表示はシンプルにする。
- 集計方法や集計期間などの内部仕様を画面に表示しない。

### 衝動ごとのビジュアル方針

#### 一揆したい

表現するもの：人々が立ち上がる、集結する、声を上げる機運。

具体的なモチーフ：
- 人々の集まり
- デモ行進
- 旗やプラカード
- 人々の集団が広がっていく様子

怒りを表す赤い光や抽象的なエネルギーだけでは不十分。人々が立ち上がる光景によって意味が直感的に伝わること。

#### 国外脱出したい

表現するもの：現在の場所から離れ、国外へ出たいという機運。

具体的なモチーフ：
- 飛行機
- 空港
- 出発する人々
- 地球から外へ伸びる航路
- 飛び立つ飛行機の増加

単なる青い光や粒子の流出ではなく、国外へ移動するイメージが明確に伝わること。

#### 祭りたい

表現するもの：人々が集まり、盛り上がり、楽しみたいという機運。

具体的なモチーフ：
- 花火
- 提灯
- 祭りのにぎわい
- 人々が集まる様子
- 踊りや祝祭の光景

投票が増えるほど花火や光、にぎわいが増していくこと。

### 共通のビジュアル原則

- 抽象的なエネルギー表現だけに依存しない。
- 文字を読まなくても衝動の意味が伝わること。
- 具体的で分かりやすく、派手で楽しい表現を優先する。
- 地球の形そのものを破壊・変形させる演出は採用しない。
- 地球上の人々の意志や機運が変化していることを表現する。
- 実際に起きたニュースや事件と誤認させるような表現は避ける。

## Activity 3：衝動を選ぶ

### ユーザーの目的

自分が現在感じている衝動を簡単に選びたい。

### User Stories

- ユーザーとして、3つの衝動をそれぞれ独立した画面で見たい。
- ユーザーとして、横スクロールで別の衝動に切り替えたい。
- ユーザーとして、アイコンを見て衝動の意味を直感的に理解したい。
- ユーザーとして、画面を切り替える際にページ全体の再読み込みをしたくない。

### Acceptance Criteria

- 既存の横スクロール構造を維持する。
- 1画面につき1つの衝動を表示する。
- スマートフォンでは横スワイプで切り替えられる。
- PCでは矢印キーや画面上の操作で切り替えられる。
- 画面切り替え時にページ全体の再読み込みを発生させない。
- 現在選択している画面が分かるようにする。
- 各画面に衝動のアイコンと名称を表示する。

---

## Activity 4：投票する

### ユーザーの目的

自分の衝動を何度か表明し、気持ちよく操作を楽しみたい。

### User Stories

- ユーザーとして、投票ボタンを押して衝動を表明したい。
- ユーザーとして、投票するたびに異なる演出を楽しみたい。
- ユーザーとして、何度も投票して異なる演出を見たい。
- ユーザーとして、たまに珍しい演出を見て驚きたい。
- ユーザーとして、投票上限に達するまでは何度も投票したい。

### Acceptance Criteria

- 投票操作は分かりやすく、押しやすい。
- 投票操作のたびに何らかの視覚的フィードバックがある。
- 演出は複数のパターンからランダムに選択される。
- 通常演出だけでなく、特殊演出や低確率のレア演出を用意する。
- 直前と同じ演出が連続しにくい仕組みを検討する。
- 衝動ごとに、その衝動の意味に合った演出を用意する。
- 投票のたびに発生する一時的な演出と、集計結果による地球全体の状態変化は分離する。
- 投票操作によって地球そのものが破壊されたり、物理的に変形したりする表現は避ける。

---

## Activity 5：投票の集計と世界への反映

### ユーザーの目的

自分だけではなく、他の人々の衝動も集まって世界の空気になっていることを感じたい。

### User Stories

- ユーザーとして、投票が他のユーザーの投票と集計されていることを知りたい。
- ユーザーとして、同じ衝動を持つ人が増えるほど、その衝動の存在感が強まる様子を見たい。
- ユーザーとして、他のユーザーの投票による変化もリアルタイムに感じたい。
- ユーザーとして、自分一人の投票ではなく、集合的な意志が世界を変えていることを感じたい。

### Acceptance Criteria

- 3つの衝動は独立して集計する。
- ある衝動への投票は、他の衝動の集計に影響しない。
- バックエンドに保存された投票データを利用する。
- 複数ユーザー間で集計結果が更新される。
- 集計結果に応じて地球のビジュアルが変化する。
- 集計結果が少ない場合でも、基本演出を維持する。
- 個人の投票操作による演出と、集合的な集計結果による演出を混同させない。

### 集計方針

既存の集計仕様を基本として維持する。

- 集計対象は直近12時間の有効投票。
- 1ユーザーあたり、各衝動について12時間内に最大10回まで投票できる。（2026-11-01 変更：最大100回。§9.1 Q-20）
- 3つの衝動の投票上限は独立している。
- 投票1回につき1票として扱う既存仕様を基本とする。
- 12時間を経過した投票は集計対象から外れ、投票可能回数も回復する。
- 表示数値は有効投票数。
- 集計方式や12時間という期間はUIに表示しない。

ただし、今後は一人の連打が全体の集計を過度に左右しないよう、寄与度を調整する方式も検討する。

その場合は、投票回数と集計上の寄与度を分離し、エンターテインメント性と集計の信頼性を両立させる。

※既存のバックエンド仕様を確認したうえで変更範囲を判断すること。承認なしに集計ロジックを変更しない。

---

## Activity 6：位置情報による演出

### ユーザーの目的

日本のどこで衝動が生まれているかを、地球上の視覚表現に反映させたい。

### User Stories

- ユーザーとして、位置情報を許可した場合、自分がいる地域に対応する演出を見たい。
- ユーザーとして、位置情報を許可しなくても通常どおり投票したい。
- ユーザーとして、自分の正確な住所や位置情報を他人に知られたくない。

### Acceptance Criteria

- 初期対象は日本。
- ブラウザのGeolocation APIによる位置情報取得を検討する。
- 位置情報取得は任意とする。
- 位置情報を拒否しても全機能を利用できる。
- 正確な位置情報を公開しない。
- 表現する位置は国・広域地域などに丸める。
- 個々の投票者を特定できる位置表示は行わない。
- 位置情報が取得できない場合は、位置に依存しない全体演出に切り替える。

位置情報を利用する場合の保存範囲・保存期間・利用目的は、プライバシー上の観点から別途確認する。

---

## Activity 7：他の衝動を試す

### ユーザーの目的

他の衝動の状態や演出も見てみたい。

### User Stories

- ユーザーとして、横スクロールで他の衝動画面を見たい。
- ユーザーとして、衝動ごとの異なる世界観を楽しみたい。
- ユーザーとして、他の衝動にも投票してみたい。

### Acceptance Criteria

- 3つの衝動画面をシームレスに切り替えられる。
- 各画面は独立した集計状態とビジュアル状態を持つ。
- 他の衝動の投票が現在の画面の状態に混ざらない。
- 画面切り替え時に再読み込みを発生させない。

---

## Activity 8：共有する

### ユーザーの目的

面白い世界の状態や珍しい演出を他の人に見せたい。

### User Stories

- ユーザーとして、現在の地球の状態をSNSで共有したい。
- ユーザーとして、珍しい演出を見たことを他の人に見せたい。
- SNSで見た人として、そのビジュアルからアプリに興味を持ちたい。

### Acceptance Criteria

- 共有する場合は、地球のビジュアルが主役になる。
- 画像や共有内容は、SNS上で見たときに意味が伝わる。
- アプリへの導線を含められる。
- 共有機能はコア体験の完成後に実装する。
- 共有を強制しない。

# 5. 非機能要件・設計上の注意

### パフォーマンス

- モバイル端末でも快適に動作する。
- 3D表現や粒子演出によって操作性が損なわれない。
- 演出中も投票操作が不自然にブロックされない。
- 連続投票に対応できる。
- 画面切り替え時に不要な再読み込みを発生させない。

### データの信頼性

- 実際の投票数と演出用の値を区別する。
- 実際の投票数を恣意的に水増ししない。
- 演出の迫力は、実数の改ざんではなく、ビジュアル側の非線形な表現によって実現する。
- 集計方式の変更はバックエンドの既存仕様を確認してから行う。

### プライバシー

- 位置情報は任意取得。
- 正確な位置情報を公開しない。
- 位置情報を取得できなくてもサービスを利用できる。

### デザイン

- 抽象的なエネルギー表現だけで意味を伝えようとしない。
- 具体的なモチーフを優先する。
- 地球であることが一目で分かる。
- 衝動ごとの世界観を明確に区別する。
- 派手さと分かりやすさを重視する。
- 装飾的な情報や機能を増やしすぎない。

# 6. Claude Codeへの作業指示

このUSMを今後の開発の基準とする。

ただし、実装を始める前に以下を実施すること。

1. 現在のソースコードを確認する。
2. 既存の画面構造とコンポーネント構成を把握する。
3. 既存バックエンドとAPIの仕様を確認する。
4. 現在の投票・集計・制限ロジックを確認する。
5. 本USMと現在の実装の差分を整理する。
6. 変更が必要な機能と、維持すべき機能を区別する。
7. 実装方針を提案する。

### 特に重要な注意事項

- バックエンドは既に存在する。新規バックエンドを作る前提にしない。
- 現在動作している投票機能や集計ロジックを、勝手に置き換えない。
- 既存の横スクロールによる画面構成を維持する。
- 3つの衝動をひとつの地球に混ぜない。
- 衝動ごとに独立した地球と演出を持たせる。
- ユーザーの一票によって地球が物理的に破壊されるような演出にしない。
- 投票によって表現するのは、社会全体の意志や機運の高まりである。
- 具体的で分かりやすい演出を優先し、抽象的なエネルギー表現だけで済ませない。
- 既存実装を確認せずに仕様を推測して変更しない。
- 不明点や矛盾点があれば、実装前に質問する。

### 成果物

まず、既存実装と本USMの差分をまとめたうえで、改修計画を提示すること。

この段階では、ユーザーの承認を得るまで大規模な実装変更を開始しない。

| 既存の横スクロール構造 | `app/components/MainScreen.vue`、`app/composables/useSwipe.ts`・`useLoopTrack.ts`（端から端へループする） |

# 8. 姉妹リポジトリとの主な違い（ハーネス作成時に追記）

| 観点 | 姉妹リポジトリ | このリポジトリ（本 USM） |
|---|---|---|
| 主役 | 集計数（画面で最も大きな文字） | 衝動ごとの地球とモチーフの演出。数字はシンプル |
| 投票操作 | エンブレムを押すと1票。専用ボタンなし | 「投票ボタン」（Q-04） |
| 投票時の演出 | 揺れ・拡大・+1・フラッシュ（固定） | 複数パターンからランダム、特殊・レア演出あり |
| 集計による変化 | 数値のみ | 地球上の現象の規模・頻度・密度が変わる |
| 位置情報 | なし | 任意取得で地域演出（次の段階） |
